# The `.peek` session format

A `.peek` file holds the network calls Peek recorded in an app: one session,
written on the device and read anywhere — by Peek itself, by
[Peek Pro](https://github.com/artdima/peek) on the desktop, by a script. The
same entry lines travel as frames between a device and a desktop viewer.

This document is the source of truth for the format. It is written so that a
reader can be built from it without looking at Peek's Dart code. The reference
files in [`fixtures/sessions/`](fixtures/sessions/) are generated by Peek's
tests and fail them when they drift, so they always show what Peek writes
today.

Format version described here: **1**.

## At a glance

```
{"format":"peek","formatVersion":1,"peekVersion":"2.0.0","name":"Acme Shop","platform":"ios","osVersion":"26.0","startedAt":"2026-09-10T12:00:00.000Z"}
{"id":"e1","source":"dio","startedAt":"2026-09-10T12:00:00.000Z","completedAt":"2026-09-10T12:00:00.120Z","request":{"method":"GET","url":"https://api.example.com/users"},"response":{"status":200,"headers":[["Content-Type","application/json; charset=utf-8"]],"body":{"kind":"text","text":"[{\"id\":1}]","type":"application/json; charset=utf-8"}}}
{"id":"e4","source":"talker","startedAt":"2026-09-10T12:00:03.000Z","request":{"method":"GET","url":"https://api.example.com/slow"}}
{"id":"e5","source":"talker","startedAt":"2026-09-10T12:00:04.000Z","completedAt":"2026-09-10T12:00:09.000Z","pinned":true,"request":{"method":"DELETE","url":"https://api.example.com/users/1"},"failure":{"kind":"timeout","message":"Receive timeout"}}
```

- The file is **UTF-8** text in **JSON Lines**: one JSON value per line.
- The **first line is the header**, every line after it is **one call** (an
  *entry*).
- Lines end with `\n`, the last one included. JSON escapes line breaks inside
  strings, so a value never spans two lines.
- There is no closing line and no count: a file can be appended to while calls
  arrive, and a file cut off mid-write loses only its last line.

## Reading a file

1. Read the text as UTF-8. Drop a leading byte order mark if there is one.
2. Split it into lines on `\n`; strip a trailing `\r` from each (files may have
   passed through Windows). Ignore lines that are empty or only whitespace.
3. The first remaining line is the header — see [Header](#header). If there is
   no such line, or it is not a valid header, the file is **not a session**:
   refuse the whole file.
4. Every later line is an entry — see [Entry](#entry). A line that is not
   valid JSON, or not a valid entry, is **skipped and counted**; reading goes
   on. Report the count ("2 lines couldn't be read"), never fail the file for
   it.
5. The same `id` can appear on more than one line, because a writer may append
   a call when it starts and again when it completes. The **last line wins**,
   and the entry **keeps the position of its first line**.

The order of entries is the order in which their ids first appear, which is the
order the calls started in.

### Leniency

A newer writer and an older reader, or the reverse, meet all the time. A reader
therefore:

- **ignores keys it does not know**, at every level (except inside `extra`,
  where every key is data);
- maps **enum values it does not know** to a fallback, as each enum below says;
- treats a key whose value is `null` like a key that is absent;
- skips the entry — not the file — when a required key is missing or has the
  wrong JSON type.

A writer leaves out every optional key whose value is empty or the default.
A reader must supply the default listed for it.

## Versions

`formatVersion` is an integer, separate from the Peek package version.

| The file's `formatVersion` | The reader |
|---|---|
| equal to the version it knows | reads it |
| **greater** | reads what it can, following the leniency rules, and warns that the file was written by a newer Peek |
| **smaller than 1**, or not an integer | refuses the file |

The version only goes up when an older reader would **misread** a file — read
it without complaint and show something wrong. New optional keys and new enum
values do not raise it: the leniency rules already cover them.

## Header

The first line: a JSON object.

| Key | Type | Required | Meaning |
|---|---|---|---|
| `format` | string | yes | Always `"peek"`. Anything else — or no `format` — means the file is not a Peek session. |
| `formatVersion` | integer | yes | See [Versions](#versions). |
| `peekVersion` | string | yes | The version of the Peek package that wrote the file, such as `"2.0.0"`. Informational. |
| `name` | string | no | What the app calls itself, as the app configured it (`PeekOptions.name`). Absent when the app did not say. |
| `platform` | string | yes | Where the app ran: `android`, `ios`, `macos`, `windows`, `linux`, `fuchsia`, `web` or `unknown`. Expect other values from newer writers; show them as they are. |
| `osVersion` | string | no | The operating system version, such as `"26.0"`. Written only where it reads as one (iOS, macOS); absent on Android, web and elsewhere. |
| `startedAt` | [time](#times) | yes | When the session began. |

Peek cannot learn the app's display name, its bundle id or package name, or the
device model from Dart, so the header does not have them. A viewer without
`name` shows the platform instead.

## Entry

One network call: a JSON object.

| Key | Type | Required | Meaning |
|---|---|---|---|
| `id` | string | yes | Identifies the call within the session. Never empty. |
| `source` | string | yes | Which adapter recorded it: `dio`, `chopper`, `http`, `talker`, `talker/dio`, … Free text; show it as it is. |
| `startedAt` | [time](#times) | yes | When the call started. |
| `completedAt` | [time](#times) | see below | When it finished. |
| `pinned` | boolean | no | `true` when the user pinned the call. Only `true` is written; default `false`. |
| `request` | [Request](#request) | yes | What was sent. |
| `response` | [Response](#response) | no | What came back, if anything did. |
| `failure` | [Failure](#failure) | no | What went wrong, if anything did. |
| `timings` | [Timings](#timings) | no | Where the time went, for sources that report it. |

`completedAt` is present **exactly** when `response` or `failure` is. An entry
that breaks this rule is invalid and skipped.

The state of a call is not written; it follows from the keys:

| `failure` | `response` | State |
|---|---|---|
| present | any | **failed** |
| absent | present | **completed** |
| absent | absent | **pending** — still in flight when the line was written |

A failed call can have a response too: `badResponse` failures carry the
response that caused them.

Its duration is `completedAt − startedAt`, never negative (show zero if the
clock went backwards). A pending call has no duration.

### Request

| Key | Type | Required | Default | Meaning |
|---|---|---|---|---|
| `method` | string | yes | | `GET`, `POST`, … as sent. |
| `url` | string | yes | | The full URL, query included. A value that is not a URL makes the entry invalid. |
| `headers` | [Headers](#headers) | no | none | |
| `body` | [Body](#body) | no | empty | |
| `extra` | object | no | `{}` | Whatever else the adapter recorded about the request (retry count, trace id, …). Keys and values are data: any JSON value; values JSON cannot hold were written as their string form. |

### Response

| Key | Type | Required | Default | Meaning |
|---|---|---|---|---|
| `status` | integer | yes | | The HTTP status code. |
| `message` | string | no | none | The reason phrase, such as `"Not Found"`, when the source reported one. |
| `headers` | [Headers](#headers) | no | none | |
| `body` | [Body](#body) | no | empty | |
| `redirects` | array of Redirect | no | `[]` | The redirects followed before this response, in order. |

A Redirect is an object:

| Key | Type | Required | Meaning |
|---|---|---|---|
| `status` | integer | yes | The redirect's status code, such as `301`. |
| `method` | string | yes | The method of the request that followed it. |
| `location` | string | yes | Where it pointed. |

### Headers

An array of `[name, value]` pairs, both strings:

```json
[["Content-Type","application/json"],["Set-Cookie","a=1; Path=/"],["Set-Cookie","b=2"]]
```

- Names are **case-insensitive**. All values of one name are written together,
  in the order they arrived; names come in the order they were first seen, in
  the casing they were first seen in.
- A repeated name gives one pair per value. Do not join `Set-Cookie` values.
- Cookies are not written separately: read them from `Cookie` and `Set-Cookie`.
- A value masked on the device reads `*****` (or whatever mask the app set).
  Masking happens before the file is written, so there is nothing to unmask.

### Body

An object with a `kind` and what that kind holds. Every kind may carry:

| Key | Type | Meaning |
|---|---|---|
| `type` | string | The body's media type as a `Content-Type` value: `type/subtype` plus parameters, such as `application/json; charset=utf-8`. Ignore a value that is not `type/subtype`. |

The kinds:

**`empty`** — no body. Rarely written, since an empty body is left out.

**`text`** — a body held as text.

| Key | Type | Required | Meaning |
|---|---|---|---|
| `text` | string | yes | The captured text. |
| `size` | integer | no | Present only when the body was **cut off**: the full size in bytes. The captured size is the UTF-8 length of `text`. |

**`bytes`** — a binary body.

| Key | Type | Required | Meaning |
|---|---|---|---|
| `bytes` | string | yes | The captured bytes in standard base64 (RFC 4648 §4, with padding). |
| `size` | integer | no | Present only when the body was **cut off**: the full size in bytes. |

**`form`** — a form: `application/x-www-form-urlencoded` or
`multipart/form-data`.

| Key | Type | Required | Default | Meaning |
|---|---|---|---|---|
| `fields` | array of `[name, value]` | no | `[]` | Text fields, in order. |
| `files` | array of File | no | `[]` | File parts, in order. Their content is not recorded. |

A File is an object: `name` (string, required — the form field), `filename`
(string), `type` (media type string), `size` (integer, bytes).

**`unavailable`** — there was a body, but it was not captured.

| Key | Type | Required | Meaning |
|---|---|---|---|
| `reason` | string | yes | `streamed` — a stream that was never buffered; `tooLarge` — over the capture limit; `notCaptured` — the source never handed it over; `unreadable` — it could not be read or decoded. Unknown values read as `notCaptured`. |
| `size` | integer | no | The full size in bytes, when known. |

**Any other `kind`** comes from a newer writer. Read it as `unavailable` with
reason `notCaptured`, keeping its `type` and `size`: the body exists, but not in
a form this reader holds.

A cut-off body (`size` greater than what was captured) should say so: "Showing
512 KB of 3.1 MB".

### Failure

| Key | Type | Required | Meaning |
|---|---|---|---|
| `kind` | string | yes | `timeout` — connecting, sending or receiving took too long; `connection` — the connection could not be made or dropped; `badCertificate` — the server certificate was rejected; `cancelled` — the app cancelled the call; `badResponse` — a response arrived with a status the client treats as an error; `unknown` — anything else. Unknown values read as `unknown`. |
| `message` | string | yes | A short, human-readable message. |
| `details` | string | no | The original error, as text. |
| `stackTrace` | string | no | The Dart stack trace where the call failed, as text: frames `#0 …`, `#1 …`, lines separated by `\n`, possibly `<asynchronous suspension>` between them. |

### Timings

An object of phases in **milliseconds** (numbers; fractions carry
microseconds). Every phase is optional; a phase the source did not report is
absent, not `0`. The names follow HAR:

| Key | Phase |
|---|---|
| `blocked` | Waiting for a connection from the pool. |
| `dns` | DNS resolution. |
| `connect` | Opening the TCP connection — TLS included when `ssl` is absent. |
| `ssl` | The TLS handshake. |
| `send` | Sending the request. |
| `wait` | Waiting for the first byte of the response. |
| `receive` | Receiving the response. |

Most sources report no phases at all; then `timings` is absent and only
`completedAt − startedAt` is known.

### Times

Every time is an ISO 8601 string in **UTC** with a `Z` suffix and a fraction of
a second: three digits (`2026-09-10T12:00:00.120Z`), or six when there are
microseconds (`2026-09-10T12:00:22.187500Z`). A reader should accept any number
of fraction digits and treat the time as UTC. A value that is not a time makes
the entry (or the header) invalid.

## Reference files

[`fixtures/sessions/`](fixtures/sessions/) holds files every reader should be
tested on. [`manifest.json`](fixtures/sessions/manifest.json) says what reading
each must give: the header's `formatVersion`, whether it is `newerFormat`, the
entry ids in order and the number of `skipped` lines — or `"error": true` for a
file that must be refused.

| File | What it shows |
|---|---|
| `basic.peek` | Every shape Peek writes: pending, completed and failed calls; text, JSON, bytes, form, multipart, cut-off and unavailable bodies; redirects; repeated headers; timings with fractions; a failure with details and a stack trace; `extra`; non-ASCII text. |
| `header-only.peek` | A session with no calls. |
| `broken-line.peek` | A line cut off halfway, a line missing its request and a blank line among good ones: two skipped. |
| `appended.peek` | A call written pending, then again completed: one entry, completed, in the first line's place. |
| `unknown-keys.peek` | `basic.peek` with an unknown key added to every object: must read exactly like `basic.peek`. |
| `future-version.peek` | Format 2: an unknown header key, a body of an unknown kind (reads as `unavailable`/`notCaptured` with its type and size), an unknown failure kind (reads as `unknown`) and a line of an unknown shape (skipped). |
| `old-version.peek` | Format 0: refused. |
| `not-a-session.peek` | JSON Lines, but not a session: refused. |
| `empty.peek` | No lines at all: refused. |

Peek regenerates these with `dart run melos run spec:update`; a plain test run
fails when a file differs from what Peek writes.

## Changes to the format

Any change starts here, in this document and the reference files, together
with the Dart code — and, when an older reader would misread the result, with a
new `formatVersion`. Readers elsewhere (Peek Pro) follow from this document.
